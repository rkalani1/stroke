# r3-shell-search — 2026-10-22

Unit: shell-search (round-3 verification fixes for 7.9.0). It covers the 12 findings in the `shell-search` slice: Evidence counts and bottom lines, global search, the Evidence and Calculators filters, the offline banner and first-session offline reference, and four keyboard-focus findings in the app shell.

The worktree branch was created at 7.8.0 (`af21b07`) with no changes. As the task instructs, I reset it to the 7.9.0 integration commit `4d13e0e` before any edit. I re-checked every finding at that HEAD. None had been fixed by the encounter-fixes or evidence-fixes commits (8af8c59..4d13e0e). The 48 rewritten bottom lines still split correctly, and all 92 shipped bottom lines are unchanged by the new abbreviation rule (compared before and after).

Owned files changed: `src/reference-search.js`, `src/quick-search-index.js` (normalize, searchIndex and ranking only), `src/calculator-utilities.js` (`matchesCalculatorSearch` only), `src/components/QuickSearch.jsx` (the no-matches hint and status lines, and the `retry` they use), `src/reference-resource.js`, `src/Reference.jsx`, `src/app.jsx` and `src/design/shell.css`. Tests: the new `tests/shell-search-2026-10-22.test.jsx` and one assertion in `tests/design-2026-10-21.test.jsx`. The service worker did not need a change: `service-worker.js` is hand-maintained with generated marker regions, and the first-session fix reads its existing precache from the page.

## 3. Code changes (summary)

- `src/reference-search.js`: exported `normalizeSearch` with the shared alias table; `wordStart`/`hasTerm` for short letter-only terms; `recommendationGroups()`; case-insensitive `ABBREVIATION_END` with month and other abbreviations; the referenceText header follows `recommendationGroups`.
- `src/quick-search-index.js`: imports `normalizeSearch` (the local normalize, including the ₂/² replacements and the afib/tpa-only aliases, is removed); short-term word-start matching; exact multi-word keyword bonus (+10, above the title-prefix +8).
- `src/calculator-utilities.js`: `matchesCalculatorSearch` uses `normalizeSearch` on the query and the text, and keeps the raw compact text.
- `src/components/QuickSearch.jsx`: index-state hint, Retry, and status line.
- `src/reference-resource.js`: precache fallback validated with `validReferenceData`.
- `src/Reference.jsx`: graded and ungraded counts and headings; tall-row keyboard reveal; offline-aware failure message.
- `src/app.jsx`: offline banner from controller state and `offlineStatus`; Tab-reveal for text areas outside Protocols; Later → focus More. To offset these bytes I removed the unreachable GCS branch of the Encounter tool gate: `gcs` is already excluded by `!['nihss','mrs','crcl','gcs'].includes(route.tool)`, and Encounter always renders `#calc-gcs`. This makes the "GCS opens with ICH, SAH or CVT." string dead, so I removed it. ICH volume and ICH severity keep "This calculator needs an ICH encounter." and "Set ICH".
- `src/design/shell.css`: one rule for the case bar's top margin; the strip comment is updated.

## 6. Protocols observations (report only)

## 7. Unresolved uncertainties

- `navigator.serviceWorker.controller` decides the banner at render time. A tab that becomes controlled later without a reload (only after an explicit update, which reloads) is not a practical case.
- The Tab-reveal relies on Chrome placing the caret before keyup. It was verified in Chromium only; other browsers keep their own focus scrolling, and the handler can only add a scroll.
